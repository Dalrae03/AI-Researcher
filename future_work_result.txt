### [Future Work Idea 1]

**근거 논문**: [A Prompt-Based Method for Source Code Summarization], [Evaluating the Factual Correctness of Code Summaries]

**논문의 주장 및 문제제기**:
[A Prompt-Based Method for Source Code Summarization] 논문은 CodeT5와 같은 사전학습 모델을 사용하여 프롬프트 기반으로 소스 코드 요약을 생성하는 방법의 우수성을 주장했다. 이 방법은 기존 seq2seq 모델보다 더 자연스럽고 정확한 요약을 생성했다. 그러나 이 논문은 모델의 성능 평가를 BLEU, ROUGE와 같은 전통적인 텍스트 유사도 기반 지표에 의존했다. 한편 [Evaluating the Factual Correctness of Code Summaries] 논문은 이러한 전통적 지표가 요약문의 사실적 정확성을 제대로 평가하지 못한다는 문제를 제기했다. 텍스트는 유사하지만 코드의 핵심 로직을 잘못 설명하는 경우가 많다는 것이다.

**논문의 제안 및 시도**:
[A Prompt-Based Method for Source Code Summarization]은 `[LANG]: <code> [SEP] The code is trying to: <mask>`와 같은 프롬프트 템플릿을 통해 모델이 빈칸을 채우도록 학습시켜 SOTA 성능을 달성했다. 이 방법은 생성 품질이 높다는 장점이 있다. 하지만 [Evaluating the Factual Correctness of Code Summaries] 논문의 지적처럼, 이 모델이 생성한 요약이 실제로 코드의 동작과 일치하는지에 대한 검증은 부족하다(B).

**미비한 부분 — 연구 공백 (B)**:
프롬프트 기반 모델이 생성한 요약문의 '사실적 정확성(Factual Correctness)'에 대한 평가 및 최적화가 이루어지지 않았다. 모델이 문법적으로 유창하고 참조 요약과 유사한 문장을 생성할 수는 있지만, 그 내용이 코드의 실제 기능을 정확히 반영하는지는 검증되지 않았다.

**핵심 주장 및 근거**:
[A Prompt-Based Method for Source Code Summarization] 논문은 프롬프트 기반 접근법을 통해 코드 요약의 SOTA 성능을 달성했다고 주장했다. 이 과정에서 기존 seq2seq 모델의 한계를 극복했지만, 성능 평가는 BLEU/ROUGE에 머물렀다. 한편, [Evaluating the Factual Correctness of Code Summaries] 논문은 BLEU/ROUGE 점수가 높아도 사실 관계가 틀린 요약이 생성될 수 있음을 보이며, 코드와 요약문에서 각각 '팩트(Fact)'를 추출하여 비교하는 새로운 평가 지표(Fact Precision/Recall)를 제안했다. 두 논문을 종합하면, 최신 생성 모델의 성능을 더욱 의미 있는 척도, 즉 사실적 정확성으로 평가하고 이를 기반으로 모델을 개선하려는 시도는 아직 이루어지지 않았다는 공백이 드러난다.

**연구 공백 및 제안**:
따라서 프롬프트 기반 생성 모델의 학습 과정에 사실적 정확성 지표를 직접적으로 통합하는 연구를 통해, 단순히 텍스트적으로 유사한 요약이 아닌, 코드의 핵심 기능을 정확히 설명하는 요약을 생성하도록 모델을 최적화할 수 있을 것이다. 이는 두 논문이 각자 다룬 '생성'과 '평가'의 영역을 결합하는 새로운 시도이다.

**제안하는 연구 방향**:
[Evaluating the Factual Correctness of Code Summaries]에서 제안된 팩트 추출 및 비교 방법론을 활용하여, 프롬프트 기반 모델의 학습 목표 함수(Objective Function)를 재설계하는 연구를 제안한다. 예를 들어, 강화학습(Reinforcement Learning)의 보상(Reward) 함수로 Fact F1-score를 사용하여, 사실적으로 더 정확한 요약을 생성할 때 모델이 더 높은 보상을 받도록 학습시킬 수 있다.

**예상 기여**:
이 연구가 성공하면, 코드 요약 모델이 더 신뢰할 수 있고 실용적인 결과물을 생성하게 할 수 있다. 개발자가 잘못된 요약 정보로 인해 버그를 만들거나 코드의 의도를 오해하는 위험을 크게 줄일 수 있으며, 코드 요약 기술의 산업적 활용도를 높이는 데 기여할 것이다.

**GitHub Novelty Check**:
제시된 GitHub 검색 결과(Positional Attention, Graph-Assisted Hierarchical RL, LightGCN)는 본 제안과 직접적인 관련이 적다. `Graph-Assisted Stitching`이 강화학습(RL)을 다루고 있지만, 이는 오프라인 계층적 강화학습의 정책(policy)을 잇는(stitching) 방법론에 관한 것으로, 코드 요약의 사실적 정확성을 보상 함수로 사용하는 자연어 생성 모델 튜닝과는 거리가 멀다. 따라서 '사실적 정확성' 지표를 RL의 보상 함수로 활용하여 코드 요약 모델을 미세조정하는 아이디어는 여전히 독창적인 연구 방향이다.

### [Future Work Idea 2]

**근거 논문**: [A Prompt-Based Method for Source Code Summarization]

**논문의 주장 및 문제제기**:
이 논문은 코드 요약 태스크를 "빈칸 채우기" 문제로 재구성하는 프롬프트 기반 접근법을 통해 기존 모델들의 성능을 뛰어넘을 수 있다고 주장했다. 이 접근법은 사전학습 언어 모델의 능력을 효과적으로 활용하여 유창한 요약을 생성하는 데 성공했다. 하지만 논문 스스로가 인정한 한계점으로, 사용된 프롬프트 템플릿이 연구자에 의해 수동으로 설계되고 고정되어 있다는 문제가 있었다.

**논문의 제안 및 시도**:
이 논문은 `"[LANG]: <code> [SEP] The code is trying to: <mask>"`라는 고정된 형태의 프롬프트를 사용하여 CodeT5 모델을 학습시켰다. 이 방법은 특정 데이터셋에서는 높은 성능을 보였지만, 프롬프트의 형태나 단어 선택에 따라 모델의 성능이 크게 좌우될 수 있음에도 불구하고, 최적의 프롬프트를 찾는 과정은 탐구되지 않았다(B).

**미비한 부분 — 연구 공백 (B)**:
코드 요약 태스크에 가장 효과적인 프롬프트를 자동으로 탐색하거나 생성하는 방법론이 부재하다. 수동으로 설계된 프롬프트는 최적이 아닐 수 있으며, 다른 프로그래밍 언어나 다른 종류의 코드에 대해서는 비효율적일 수 있다.

**핵심 주장 및 근거**:
[A Prompt-Based Method for Source Code Summarization] 논문은 프롬프트 기반 방법론의 잠재력을 입증했다. 이 논문은 고정된 단일 프롬프트를 사용해 SOTA 결과를 얻었지만, 논문의 'Future Work' 섹션에서 직접 "자동으로 프롬프트를 생성하거나 최적화하는 방법을 탐색하면 더 나은 결과를 얻을 수 있다"고 명시했다. 이는 현재의 성공이 프롬프트 엔지니어링의 초기 단계에 불과하며, 이 부분을 자동화하고 최적화하는 것이 모델 성능을 한 단계 더 끌어올릴 핵심 과제임을 시사한다.

**연구 공백 및 제안**:
따라서 위 근거로부터 도출되는 미해결 부분은 '최적 프롬프트 자동 탐색'이다. 이를 해결하기 위해 입력 소스 코드의 특성(예: 복잡도, 길이, 사용된 API)을 분석하여 동적으로 가장 적합한 프롬프트를 생성하거나, 여러 프롬프트 후보군 중에서 최적의 프롬프트를 선택하는 방법을 연구할 수 있다.

**제안하는 연구 방향**:
Prompt-Tuning이나 In-Context Learning과 같은 최신 기법을 코드 요약에 적용하는 연구를 제안한다. 구체적으로, 코드의 구조적, 의미적 특징을 입력으로 받아 최적의 프롬프트 템플릿(텍스트)이나 연속적인 프롬프트 임베딩(Soft Prompt)을 생성하는 작은 네트워크를 별도로 학습시키는 방법론을 개발할 수 있다. 이를 통해 각 코드에 맞는 '맞춤형' 프롬프트를 동적으로 제공하여 요약 성능을 극대화할 수 있다.

**예상 기여**:
이 연구는 코드 요약 모델의 성능과 일반화 능력을 향상시킬 수 있다. 또한, 수동 프롬프트 엔지니어링에 드는 노력을 줄여주고, 다양한 프로그래밍 언어와 도메인에 더 쉽게 적응할 수 있는 강력한 코드 요약 시스템을 구축하는 데 기여할 것이다.

**GitHub Novelty Check**:
제시된 GitHub 검색 결과는 어텐션 메커니즘, 강화학습, 추천 시스템용 GCN에 초점을 맞추고 있으며, 프롬프트 엔지니어링 자동화나 Prompt-Tuning과는 전혀 관련이 없다. 코드의 특성에 따라 동적으로 프롬프트를 생성하거나 최적의 soft prompt를 학습하는 연구 방향은 제시된 리포지토리들에서 다루어지지 않은 명백한 연구 공백으로 남아있다.

### [Future Work Idea 3]

**근거 논문**: [A Prompt-Based Method for Source Code Summarization], [Graph-Based Knowledge Transfer for Unsupervised Code Summarization]

**논문의 주장 및 문제제기**:
두 논문은 각기 다른 접근법(프롬프트 기반, 그래프 기반)으로 코드 요약의 성능을 높이고자 했다. [A Prompt-Based Method for Source Code Summarization]은 트랜스포머 기반 모델을 사용했고, [Graph-Based Knowledge Transfer for Unsupervised Code Summarization]은 코드의 구조적 정보를 활용하기 위해 GNN을 사용했다. 하지만 두 논문 모두 매우 길고 복잡한 소스 코드를 처리하는 데에는 명확한 한계가 있음을 시사했다.

**논문의 제안 및 시도**:
[A Prompt-Based Method for Source Code Summarization]은 사전학습 모델의 고정된 입력 길이 제한 때문에 매우 긴 코드를 처리하는 데 어려움이 있음을 인정했다. [Graph-Based Knowledge Transfer for Unsupervised Code Summarization]은 긴 코드로부터 생성된 AST(추상 구문 트리)가 너무 커져 GNN의 연산 비용이 기하급수적으로 증가하는 문제를 지적했다. 두 방법 모두 긴 코드에 대한 확장성(Scalability)이 부족하다는 공통된 문제(B)를 안고 있다.

**미비한 부분 — 연구 공백 (B)**:
실제 산업 현장에서 흔히 볼 수 있는 수백, 수천 라인의 긴 소스 코드 파일을 효과적으로 요약하는 확장 가능한 방법론이 부재하다. 현재의 모델들은 대부분 비교적 짧은 함수나 코드 조각(snippet) 수준의 요약에 초점을 맞추고 있다.

**핵심 주장 및 근거**:
[A Prompt-Based Method for Source Code Summarization] 논문은 트랜스포머의 입력 길이 제약으로 인해 긴 코드에 대한 평가가 미흡했다고 밝혔다. 한편 [Graph-Based Knowledge Transfer for Unsupervised Code Summarization] 논문은 GNN 기반 접근법이 코드 길이가 길어질수록 AST 그래프가 너무 커져 연산이 비효율적이 되는 계산적 한계가 있음을 언급했다. 두 논문 모두 각자의 방법론적 틀 안에서 '긴 코드 처리'라는 동일한 문제에 부딪혔지만, 누구도 이 문제를 직접적으로 해결하기 위한 방안을 제시하지 않았다. 이는 현재 코드 요약 연구 분야의 중요한 기술적 공백이다.

**연구 공백 및 제안**:
따라서 두 논문이 공통으로 언급했지만 해결하지 못한 '긴 코드 요약' 문제를 해결하기 위해, 코드를 계층적으로 요약하거나 중요한 부분만 선택적으로 분석하는 새로운 아키텍처를 연구할 필요가 있다.

**제안하는 연구 방향**:
긴 소스 코드를 의미 있는 블록(예: 클래스, 함수 호출 관계)으로 분할하고, 각 블록에 대한 요약을 먼저 생성한 뒤, 이 중간 요약들을 다시 통합하여 전체 코드에 대한 최종 요약을 생성하는 '계층적 요약(Hierarchical Summarization)' 방법론을 제안한다. 예를 들어, 각 함수에 대해 GNN 기반 모델로 구조적 요약을 생성하고, 이 함수 요약들을 프롬프트 기반 모델의 입력으로 사용하여 전체 파일의 동작을 설명하는 상위 수준의 요약을 생성하는 하이브리드 접근을 시도할 수 있다.

**예상 기여**:
이 연구는 코드 요약 기술의 적용 범위를 짧은 함수 수준에서 전체 스크립트나 모듈, 클래스 파일 수준으로 확장할 수 있다. 이는 대규모 소프트웨어 시스템의 유지보수 및 분석 과정에서 개발자의 코드 이해도를 획기적으로 높이는 데 기여할 것이다.

**GitHub Novelty Check**:
`Graph-Assisted Stitching for Offline Hierarchical Reinforcement Learning` 리포지토리에 'Hierarchical'이라는 키워드가 포함되어 있지만, 이는 강화학습 에이전트의 정책을 계층적으로 구성하는 것에 관한 연구이다. 본 제안은 '긴 소스 코드'라는 데이터를 계층적으로 분해하고 요약하는 '자연어 처리' 문제에 관한 것으로, 문제 정의와 접근 방식이 완전히 다르다. 따라서 코드 요약을 위한 계층적 접근법, 특히 GNN과 트랜스포머를 결합한 하이브리드 방식은 여전히 새로운 연구 방향이다.

### [Future Work Idea 4]

**근거 논문**: [A Prompt-Based Method for Source Code Summarization], [Graph-Based Knowledge Transfer for Unsupervised Code Summarization]

**논문의 주장 및 문제제기**:
[A Prompt-Based Method for Source Code Summarization]은 텍스트 시퀀스에 강한 트랜스포머 모델을 활용해 코드 요약을 성공적으로 수행했다. 반면 [Graph-Based Knowledge Transfer for Unsupervised Code Summarization]은 코드의 구조적 정보(AST)를 GNN으로 인코딩하는 것이 중요하다고 주장하며, 순차적 정보만 보는 모델의 한계를 지적했다. 두 접근법은 각각 코드의 텍스트적 측면과 구조적 측면이라는 상호보완적인 정보에 집중하고 있다.

**논문의 제안 및 시도**:
[Graph-Based Knowledge Transfer for Unsupervised Code Summarization]은 AST 기반 GNN 인코더와 사전학습 언어 모델로부터의 단방향 지식 전이(knowledge transfer)를 결합했다. 이 방법은 구조 정보를 잘 활용했지만, 논문 스스로가 이 지식 전이가 단방향이라는 점을 한계로 언급했다(B). 즉, 텍스트의 의미 정보가 그래프 노드를 보강하지만, 그래프의 구조 정보가 텍스트 이해 과정에 직접적으로 영향을 주지는 못했다.

**미비한 부분 — 연구 공백 (B)**:
코드의 텍스트적 의미 정보와 구조적 정보를 하나의 모델 내에서 양방향으로 통합하여 상호 보완적으로 처리하는 통합 모델이 부재하다. 현재는 두 정보를 분리된 파이프라인으로 처리하거나 한쪽에서 다른 쪽으로 일방적인 정보만 전달하는 수준에 머물러 있다.

**핵심 주장 및 근거**:
[A Prompt-Based Method for Source Code Summarization] 논문은 코드의 텍스트 시퀀스를 처리하여 유창한 요약을 생성하는 데 성공했다. 한편 [Graph-Based Knowledge Transfer for Unsupervised Code Summarization] 논문은 AST 그래프로 코드 구조를 파악하는 것이 중요하다고 주장했지만, 텍스트 의미를 그래프에 주입하는 단방향 전이의 한계를 인정했다. 두 논문의 접근법을 종합해 볼 때, 코드라는 데이터는 텍스트(token sequence)인 동시에 구조(graph)를 가지고 있으므로, 이 두 가지 특성을 동시에, 그리고 상호작용적으로 학습하는 통합 아키텍처가 필요하다는 결론에 이를 수 있다. 하지만 두 논문 모두 이러한 통합적 접근은 시도하지 않았다.

**연구 공백 및 제안**:
따라서 [Graph-Based Knowledge Transfer for Unsupervised Code Summarization] 논문이 지적한 단방향 정보 흐름의 한계를 극복하고, 두 정보의 시너지를 극대화하기 위해 코드의 그래프 구조와 텍스트 순서를 함께 인코딩하는 새로운 아키텍처를 연구할 수 있다.

**제안하는 연구 방향**:
Graph-Aware Transformer와 같은 모델 구조를 코드 요약에 적용하는 연구를 제안한다. 이 모델은 트랜스포머의 셀프 어텐션(Self-Attention) 메커니즘을 수정하여, 토큰 간의 순차적 거리뿐만 아니라 AST 상에서의 구조적 관계(예: 부모-자식 노드, 형제 노드)를 어텐션 계산에 함께 반영한다. 이를 통해 모델이 "이 토큰이 코드에서 어떤 역할을 하는가(구조)"와 "이 토큰이 문맥상 어떤 의미인가(텍스트)"를 동시에 고려하여 더 깊이 있는 코드 이해를 달성할 수 있다.

**예상 기여**:
이 연구는 코드의 구문론적 구조와 의미론적 내용을 통합적으로 이해하는 차세대 코드 요약 모델의 기반이 될 수 있다. 변수명은 비슷하지만 AST 상에서 역할이 전혀 다른 코드를 구분하거나, 복잡한 제어 흐름을 더 정확히 파악하여 요약의 정확성을 크게 향상시키는 데 기여할 것이다.

**GitHub Novelty Check**:
검색 결과에 포함된 `LightGCN`은 추천 시스템을 위한 그래프 신경망 모델이며, 트랜스포머 아키텍처와는 다르다. `Positional Attention`은 트랜스포머의 위치 정보를 다루지만 그래프 구조를 통합하지는 않는다. 제안된 'Graph-Aware Transformer'는 트랜스포머의 셀프 어텐션 자체에 그래프 구조 정보를 주입하는 특정 아키텍처로, 검색된 GCN이나 일반적인 트랜스포머와는 명확히 구분된다. 따라서 코드의 AST 구조를 트랜스포머 어텐션에 직접 통합하는 이 방향은 여전히 독창적이다.

### [Future Work Idea 5]

**근거 논문**: [Evaluating the Factual Correctness of Code Summaries]

**논문의 주장 및 문제제기**:
이 논문은 기존의 BLEU/ROUGE와 같은 텍스트 유사도 기반 평가 지표가 코드 요약의 품질을 제대로 측정하지 못한다고 주장하며, '사실적 정확성'이라는 새로운 평가 패러다임을 제안했다. 이 문제는 요약 모델의 실질적인 신뢰도를 판단하는 데 있어 매우 중요하다.

**논문의 제안 및 시도**:
논문은 코드로부터는 정적 분석(static analysis)을 통해, 자연어 요약문으로부터는 NLU 기술을 통해 각각 '팩트(fact)'를 추출하고, 두 팩트 집합을 비교하여 정확성을 측정하는 방법론을 제시했다. 이 방법은 기존 지표의 한계를 명확히 보여줬지만, 논문 스스로가 팩트 추출 과정의 한계를 명시했다. 구체적으로, 정적 분석은 코드를 실행하지 않으므로 동적 행위(dynamic behavior)를 파악할 수 없고, 자연어 팩트 추출은 현재 NLU 모델의 성능에 의존적이라는 점이 한계(B)로 남았다.

**미비한 부분 — 연구 공백 (B)**:
코드의 동적 행위(예: 런타임 시 변수 값의 변화, 다형성에 따른 실제 호출 함수)나 비기능적 속성(예: 알고리즘 시간 복잡도, 잠재적 보안 취약점)과 같은 더 깊은 수준의 정보를 포괄하는 사실적 정확성 평가 방법론이 부재하다.

**핵심 주장 및 근거**:
[Evaluating the Factual Correctness of Code Summaries] 논문은 코드 요약 평가를 위한 중요한 전환점을 제시했지만, 스스로의 한계점을 명확히 했다. 'Future Work'에서 "정적 분석의 한계를 넘어 동적 분석을 통합하는 것"과 "보안 취약점이나 알고리즘 복잡도 같은 더 넓은 범위의 팩트 유형을 다루는 것"을 미래 연구 방향으로 직접 제안했다. 이는 현재의 팩트 기반 평가가 코드의 표면적인 정적 정보에 국한되어 있으며, 코드의 실제 실행 의미나 더 중요한 비기능적 속성을 평가하지 못하는 명백한 연구 공백이 존재함을 보여준다.

**연구 공백 및 제안**:
따라서 현재의 정적 팩트 추출을 넘어, 코드의 동적 행위와 비기능적 속성까지 포괄하는 확장된 사실적 정확성 평가 프레임워크를 개발하는 연구가 필요하다. 이는 요약 모델이 코드의 '숨겨진' 의도와 결과를 얼마나 잘 이해하는지 평가하는 데 필수적이다.

**제안하는 연구 방향**:
코드에 대한 동적 분석(dynamic analysis)을 평가 파이프라인에 통합하는 연구를 제안한다. 구체적으로, 테스트 케이스를 자동으로 생성하여 코드를 실행시켜보고, 실행 추적(execution trace) 로그를 분석하여 "특정 입력에 대해 함수가 특정 값을 반환한다" 또는 "루프가 평균 N번 실행된다"와 같은 동적 팩트를 추출한다. 이후, 요약문에 이러한 동적 행위에 대한 설명이 포함되어 있는지를 NLU 모델로 확인하여 동적 사실성 점수를 측정한다. 또한, 보안 스캐너나 성능 프로파일러를 연동하여 'SQL 인젝션 취약점 존재'나 '알고리즘 복잡도는 O(n^2)' 같은 비기능적 팩트도 평가 항목에 추가할 수 있다.

**예상 기여**:
이 연구는 코드 요약 모델의 평가 기준을 한 차원 높은 수준으로 끌어올릴 수 있다. 모델이 단순히 코드의 표면적 로직을 번역하는 것을 넘어, 실제 실행 결과와 잠재적 위험까지 예측하고 설명할 수 있는지 검증할 수 있게 된다. 이는 미션 크리티컬한 소프트웨어 개발에서 매우 중요한 신뢰성 높은 AI 기반 코드 보조 도구를 만드는 데 기여할 것이다.

**GitHub Novelty Check**:
제시된 GitHub 검색 결과는 본 제안의 핵심인 프로그램의 동적/정적 분석, 보안 취약점 분석, 성능 프로파일링과 전혀 관련이 없다. 이 제안은 자연어 처리(NLP) 모델의 '평가' 방법론을 소프트웨어 공학의 '프로그램 분석' 기술과 융합하는 것으로, 매우 학제적인 성격을 띤다. 검색된 리포지토리들은 이러한 융합을 시도하지 않았으므로, 제안된 연구 방향은 매우 독창적이며 중요한 연구 공백을 다룬다.
